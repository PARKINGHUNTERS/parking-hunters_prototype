## 배경 및 문제 정의

> 박진호는 목적지 근처 주차 공간에 대한 정보 부족 때문에 교통이 복잡한 곳에서의 주차가 불편합니다.

대구광역시는 인구 1.9명당 자동차 1대를 보유해 전국 특·광역시 중 3번째로 차량 밀집도가 높은 도시이며, 동성로·동대구역·수성못 등 핵심 상권과 원도심은 구조적으로 주차 수요가 몰려 불법 주정차 위반율이 높게 나타난다.

표면적으로는 "주차 공간 부족"이 원인처럼 보이지만:

- 대구시 전체 주차 확보율은 **96%대**로, 총량 관점에서는 절대적으로 부족하다고 보기 어렵다
- 더 설득력 있는 1차 원인은 **정보 비대칭**이다 — 대구시가 이미 통합주차정보시스템을 운영 중이지만 인지도가 낮아 실제 활용률이 떨어진다
- 원도심 상업지구를 방문하는 **비거주 운전자**는 지리를 몰라 "주차장이 있는데도 몰라서" 도로에 정차하는 경우가 많을 것으로 추정된다

> **핵심 가설**: 운전자가 목적지 부근 주차장의 존재·요금·혼잡 여부를 사전에 알 수 있다면, 도로 위 불법 정차 대신 정식 주차장을 선택할 가능성이 높아진다.

## 타겟 사용자

| 항목 | 내용 |
|---|---|
| 주 타겟 | 목적지 주변 주차장 위치·요금·여유공간 등의 정보 부족으로 불편함을 느끼는 운전자 (페르소나: 박진호) |
| 세부 대상 | 초보 운전자, 원도심 상업지구 초행길 방문객, 주말 나들이객 등 비거주 운전자 |
| 선정 이유 | "주차장이 없어서"가 아니라 "있는데 몰라서" 겪는 불편이므로, 정보 제공만으로 행동 변화를 기대할 수 있음 |
| 1차 범위 제외 | 배달 라이더 등 (정보 부족이 아닌 시간 압박 등 다른 요인이 원인) |

**핵심 니즈**: "내가 갈 목적지 바로 옆에, 지금(혹은 도착하는 시점에) 세울 수 있는 자리가 있는가"를 직관적이고 신뢰할 수 있게 확인하고 싶어한다.

## 목표 및 성공 지표

- 목적지 도착 전 주차장의 위치·여유공간·요금을 미리 안내하여 **탐색 배회 시간을 단축**
- 공영·민영(개방 참여) 주차장 정보를 하나의 서비스로 통합 제공
- 1차 목표 지역: **대구광역시** (원도심 상업지구 우선)

| KPI | 목표 | 설명 |
|---|---|---|
| 목적 주차장 결정 소요 시간 | 30초 이내 | 앱 진입 후 주차장 한 곳을 선택하기까지 걸리는 평균 시간 |
| 외부 내비 연동 전환율 | 베타 기간 측정 | 주차장 선택 후 '길찾기'로 외부 내비게이션 앱을 실행한 비율 |
| WAU | 베타 기간 측정 | 주간 활성 사용자 수 |
| 재방문율 | 베타 기간 측정 | 최초 사용 후 7일 이내 재사용 비율 |

## 핵심 기능 (MVP)

### F-01. 현재 위치 기반 주변 주차장 검색

GPS로 확보한 현재 위치를 기준으로 주변 주차장 4~5개를 텍스트 박스 형식으로 제공. 목적지 입력 없이 "이미 목적지 근처에 도착한 경우" 등에 사용.
- 리스트 항목: 주차장 이름, 현 위치에서의 거리, 요금, 혼잡도
- 터치 시 상세 정보(운영시간, 전체 차석, 일별 최대요금 등) 제공
- 전기차 충전 구역·장애인 전용 구역 면수는 상세 정보에 별도 표시

### F-02. 목적지 검색 기반 주변 주차장 검색

상단 검색창에 텍스트로 목적지를 입력하면 Geocoding 후 해당 주소 인근 주차장 5곳을 안내. **출발 전 1회 입력을 기본 흐름으로 설계**하여 운전 중 휴대폰 조작을 유도하지 않도록 함.

### 공통 UX 규칙 — 지도 마커

| 마커 | 의미 |
|---|---|
| 파란 핀 | 사용자가 검색한 목적지 |
| 초록 | 여유 있음 (실시간 연동) |
| 주황 | 혼잡 (실시간 연동) |
| 빨강 | 만차 (실시간 연동) |
| 회색 | 실시간 정보 미지원 — "기본 정보 제공"으로 구분 표시 |

## 화면 흐름

핵심 과업을 완료하는 최소 화면 4개로 구성한다.

```
[화면 1: 홈] --검색창 터치--> [화면 2: 검색창] --텍스트 입력+검색--> [화면 3: 목적지 주변 주차장 정보]
      |                                                                    |
      +------------------------ 텍스트 박스 터치 ---------------------------+
                                       ↓
                          [화면 4: 상세 정보]
```

| 화면 | 사용자 | 서비스 |
|---|---|---|
| 1. 홈 | 앱을 실행한다 | 현재 위치 기준 주변 주차장 4~5개(이름/거리/요금/혼잡도)를 텍스트 박스로 제공. 상단에 목적지 검색창 |
| 2. 검색창 | 검색 바를 터치, 목적지 입력 | 입력 텍스트를 주소명/장소명으로 변환(Geocoding) |
| 3. 목적지 주변 주차장 정보 | 검색 버튼 터치 후 결과 확인 | 인근 주차장 5곳을 간소화된 텍스트 박스로 제공 |
| 4. 상세 정보 | 텍스트 박스 터치 | 운영시간, 전체 차석, 일별 최대요금 등 상세 정보 제공 (화면 1·3 모두에서 동일하게 진입) |

## 실 API 연동 현황

pis.daegu.go.kr은 **인증키 + IP 화이트리스트** 방식이라, 앱이 직접 호출할 수 없습니다
(사용자 폰마다 IP가 다르고 계속 바뀜). 그래서 `server/`에 고정 IP 프록시를 뒀습니다.

```
[Flutter 앱] → [server/ (고정 IP 1대, 여기만 화이트리스트 등록)] → [pis.daegu.go.kr]
```

| 구성 | 상태 |
|---|---|
| `lib/services/pis/` (Flutter, 직접 호출용) | 클라이언트/DTO/거리계산 작성 완료 |
| `server/` (Node 프록시, 프로덕션 경로) | `/api/parking-lots/nearby` 구현 완료, 배포 필요 |
| 화면 ↔ 실 데이터 연결 | 미완료 — 요금/운영시간/전용구역 필드명 확인 후 진행 |

배포 방법(네이버클라우드플랫폼 기준)은 `server/README.md` 참고.

**확인이 더 필요한 것**: `serviceApply/prkInfo` 응답의 요금/운영시간/전기차·장애인 전용구역 필드명 (원본 JSON을 `server/`의 `/_debug/raw-basic-info`로 확인 가능), sggCd 전체 코드 목록, prkInfo가 공영/민영을 다 포함하는지 여부.
